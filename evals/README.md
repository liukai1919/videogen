# Evals — 评测防护网

Agent 的行为定义在提示词和 SKILL.md 这样的普通文本里，文本会漂移。没有固定场景集
和判分标准，每次改提示词体系、换模型、调工具描述都是碰运气。这套评测的目的：

1. 改动后抓回归（分镜模板、模型路由、红线守卫、技能缺省合并）。
2. 想改默认值？先跑出数据，再进 [DECISIONS.md](./DECISIONS.md) 台账。
3. 新人（或外部 worker）读 10 个带判分的场景，比读全部提示词源码更快建立预期。

## 怎么跑一轮

暂无自动跑分器，人工执行（外部 Agent worker 代跑是后续方向）：

1. 启动服务（`.\start.ps1` 或 `.\start-wsl.ps1`），打开工作台 `http://127.0.0.1:8020/workspace`。
2. 逐个执行 [scenarios.md](./scenarios.md) 的场景：**每个场景开一个全新会话**，
   把"用户说什么"原文贴进去，在右侧对话的工具调用内联展示里观察 agent 行为。
3. 按各场景的判分标准打分：通过 / 部分 / 不通过。
4. 结果记进 [rounds.md](./rounds.md)（commit SHA、日期、每场景得分、耗时、失败样态）。

**评的是决策与编排，不是画质。** 大多数场景看到工具调用参数正确即可判分，
不必等渲染完成——一轮全场景控制在半小时内。个别场景有前置条件（如故意停掉
ComfyUI），场景里会注明。

**烧卡警示：** 渲染一经排队**不可取消**（目前没有 cancel API），评测排进去的
渲染会一路跑完。场景里的时长因此都压在"最小可测"——够触发被测行为即可。
修订场景时不要加大渲染时长。

## 术语

- **场景（Scenario）**：一条用户请求 + 期望行为 + 判分标准。
- **轮次（Round）**：某个 commit 下跑完整场景集的一次快照。

## 回归阈值

轮次对比上一轮：**总分下降 >15%，或整轮耗时 >2×，视为回归**——回滚改动并排查，
而不是把分数解释过去。

## 什么时候加场景

- 手工测试才抓到的 bug → 固化成场景，下次自动抓。
- 新功能合并前 → 先写场景再合 PR。
- 用户报告了意外行为 → triage 时顺手写成场景。

不要写测内部实现的场景（"是否打了某条日志"）——只测用户看得见的行为。
确定性的代码行为归 `tests/` 的 pytest，这里只管模型参与的决策链。

## 沉淀为决策

同一结论在 **3 轮以上**保持稳定后，写进 [DECISIONS.md](./DECISIONS.md)：
后来者（包括 agent 自己）不带新数据不得推翻。
